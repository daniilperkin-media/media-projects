GTA 6 Clipper

A hands-off pipeline that turns a Twitch GTA VI clip into a ready-to-post vertical export: watch the category, download a rising clip, transcribe it on the RTX 4060, let an LLM chain pick the hook, then burn the whole 1080×1920 facecam-over-gameplay render with per-word yellow subtitles in a single NVENC pass — delivered to ready_to_post/ and Telegram. Posting stays manual, forever.

Python 3.12 · uvfaster-whisper turbo · CUDAMediaPipe 0.10.21FFmpeg NVENCGemini → OpenRouter → heuristicSQLitepytest CI on push

What it does

  • Monitors the category — Helix /clips for “Grand Theft Auto VI” with a view floor and a velocity window; sampled clips are scored and promoted in SQLite.
  • Transcribes on the local GPU — faster-whisper turbo with word timestamps on CUDA (RTX 4060), CPU fallback; the selftest loads it in ~3 s.
  • Scores virality in a 3-step chain — Gemini 2.5 Flash → OpenRouter gpt-4o-mini → heuristic; the pipeline still produces output with zero API keys.
  • Renders once — NVENC: facecam (preset or MediaPipe-detected) stacked over a gameplay slice, per-word ASS subtitles burned in, High profile + bt709/tv pinned so players never mis-render it.
  • Delivers, then stops — ready_to_post/YYYY-MM-DD/ gets mp4 + caption + cover; Telegram takes the file when it fits the Bot API caps (≤45 MB video). Posting is manual, by design.

The judge chain, under pressure

Sample scores through the real three-step chain — Gemini 2.5 Flash, then OpenRouter gpt-4o-mini, then the local heuristic. Switch a key off and the chain degrades without blocking; the export still lands.

The delivery-format pin

[stack]setparams=colorspace=bt709:color_primaries=bt709:
        color_trc=bt709:range=tv

Frames carry the tags; codec-level flags alone left primaries/transfer “unknown” in this ffmpeg build. Untagged or non-4:2:0 H.264 is the green-cast class — decodes fine, mis-renders in players.

OpenShorts

Long videos in, vertical shorts out. Paste a YouTube URL or drop in a file: OpenShorts transcribes it on the local GPU, proposes the cut-worthy moments with an LLM, reviews them with you in a React dashboard, then renders face-tracked, 1080-tall verticals — with karaoke captions you can restyle across six presets, one subtitle event per word.

Face-tracked framing

What it does

  • Takes a URL or a file — yt-dlp downloads (cookies ready when YouTube's bot wall bites) or a plain upload; the FastAPI job queue runs each job as an isolated main.py subprocess, two at a time by default, with state in SQLite (WAL) so a restart re-enqueues instead of losing work.
  • Transcribes on the local GPU — faster-whisper with word timestamps on the RTX 4060 (test video: 387 s → 81 segments); the same words feed the highlight picker and the caption engine.
  • Proposes the shorts — Gemini, OpenRouter or a local LM Studio model (picker per analysis) writes start/end + title picks into metadata.json; a heuristic fallback keeps the pipeline producing with zero API keys. The dashboard sends your selection to /api/generate-selected.
  • Reviews in a dashboard — React 18 / Vite with react-query polling, a job stepper, a cutting-room review player with keyboard triage, and per-clip Subtitle / Hook modals; History and Settings pages on the side.
  • Frames the faces — scene detection picks TRACK vs GENERAL per scene; TRACK follows the largest face with a smoothed cameraman; GENERAL gets a blurred-background letterbox; when faces hide, a lazily-loaded YOLOv8m person box takes over.
  • Renders, then post-processes — NVENC when the build lists it (libx264 otherwise), bt709 pinned via setparams; /api/subtitle burns karaoke ASS, /api/hook overlays hook cards, /api/edit lets Gemini write the FFmpeg filter itself.

What it does

  • Writes the script — GPT-4o-mini turns one fact into a four-scene script; retries with backoff wrap every network call. With no API key the run still completes on a sample fact with synthesised slides (only the imagery stage needs the key).
  • Renders the imagery — Flux 2 Pro draws each scene via OpenRouter; a failed slide degrades to a dark-canvas card instead of killing the run.
  • Composes the cards — PIL: resize onto the canvas, gradient, wrapped text, per-category badge, progress dots; Inter when bundled, system fonts otherwise.
  • Cuts the video — FFmpeg slideshow, 2.5 s per slide → one 10-second 1080×1920 H.264 mp4 at 30 fps.
  • Posts & remembers — TikTok Content Posting API upload with automatic token refresh, and a 2,000-topic history file so a fact never repeats.

Gothic Character Project

A gothic novel's visual, grown one generation at a time: AI-built character reference sheets, scene compositions and pose experiments — kept like an archive rather than a folder. A pure-stdlib toolchain recovers whatever text metadata the generators left behind, three manifests keep every PNG accounted for, and a five-step gate stands between a new file and the shelf. The prompting bible — visual markers, never names; diegetic sound only; no brands — is enforced, not aspirational.

@novel-translation · section live

Novel Translation

A small Python pipeline that prepares any novel EPUB for LLM translation and reassembles the result: extract → clean → split into <<<PART n>>>-marked batches → verify → translate (by hand in any chat UI, or via API) → assemble back into a book. It grew out of a real English→Ukrainian novel run — 215 chapters into 43 batch files — and ships a public-domain demo book so the whole round trip reproduces offline.

Python 3.10–3.13 · pyproject ebooklib + BeautifulSoup <<<PART n>>> markers + manifest.json stdlib-only API client MIT · v0.1.0 ruff + CI on push

The round trip, replayed

Stage by stage on the bundled demo book — four real runs, output verbatim (captured on Windows, hence the backslash paths). Click through the stages.

Markers are the contract

The demo run's three batch files, part by part — straight from manifest.json and the batch files themselves. The headings get translated by the model; the marker lines are the only reliable link between a translated block and its chapter, so they must come back exactly as they went out.

Flags that earned their keep

  • --strip REGEX — drops running headers a source EPUB repeats on every page (a regex, not a constant: the original run's banner was book-specific).
  • --insert FILE --insert-after N — splices a recovered chapter back where the source books missed one; this pipeline's origin story.
  • --story-start / --heading-regex — where the story begins and what counts as a part (Chapter N · Side Story N · Epilogue by default).
  • --batch-size N — parts per batch file (default 5, the real run's setting).
  • verify --max-chapter N --strict — continuity across a known full range, non-zero exit on issues.

Every change must pass

  • ruff check . + compileall — lint and syntax, one config in the repo
  • 15 unittest tests — synthetic EPUBs built at runtime; the API path runs on a fake transport
  • CLI smoke — novel-translate --help
  • demo round trip — prepare → verify --strict → assemble, on Python 3.10–3.13

Nothing drops silently

error: missing part(s) in the translated files: [3]

A demo run with one <<<PART 3>>> line dropped from a translated batch: assemble refuses with exit 2 — a duplicated part fails the same way. translate counts markers per batch and warns when a model returns a different number than it sent.
